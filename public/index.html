YOUR FIRST TEST

From a phone screen to a Python test

Vortex helps you find controls in an Android app, record what you do, and save those actions as a test you can run again. Start with the steps below. You do not need to write Python to record your first flow.

1. Connect2. Inspect & copy3. Record4. Save5. Replay

1. Connect your phone and app

  1. Unlock your Android phone, enable USB debugging and connect it by USB. Accept the debugging prompt on the phone.
  2. Open Server & setup → Run setup check. Follow any fixes it reports.
  3. Choose Start Appium, or Connect existing if Appium is already running.
  4. Choose your phone, enter the app package (for example com.stockpilot.b2b) and click Attach session.
  5. Click Launch app. Use Refresh screen whenever you navigate on the physical phone.

The app package identifies the installed Android app. Appium is the service that controls the phone; Vortex is the inspector and recorder you use here.

2. Inspect and copy an element

  1. Click Inspect element above the phone image. Moving over the image previews locators instantly from the captured screen.
  2. Click a control on the phone image or its row in the middle tree. Inspect mode selects it without tapping the phone.
  3. Use the Simple inspect card to choose Use text, Use ID / label or Use point. The selector and Python code appear immediately.
  4. Copy locator copies the selector value; Copy Python copies the lookup or point-tap code; Copy element copies element details as JSON.

Enable Auto-refresh screen to follow navigation on the phone. It pauses while a selection is pinned or you edit a field; click Resume live to clear the selection and continue. Viewing Tutorial or putting the browser tab in the background pauses live captures.

A WebView can expose native text even when its DOM is unavailable. Use text or ID when exposed, or choose a point and click Tap. Points are screen coordinates, depend on layout and scroll position, and do not identify an element for assertions. DOM/CSS selectors require an exposed WebView context.

Prefer a unique ID or accessibility label. “Unique on this screen” uses the captured hierarchy. “Verified on phone” means a live lookup confirmed it. Use Verify all on phone to check every candidate.

3. Create a file and record a short flow

  1. Click New file. Choose a unique test name, a module and Python output. A module is simply a folder that groups your tests.
  2. Click Create file. Vortex saves an empty starter. If you have current steps, the dialog asks you to save them or explicitly discard them first.
  3. All phone actions are together in the Actions panel beneath the selected locator. Keep Record successful actions checked. Choose Tap for taps and gestures, or Type to enter text and click Type text.
  4. Select a result, open Actions → Assert, choose a check such as Text equals, enter the expected text and click Assert. More contains swipes, waits, keyboard, links and checkpoints.

Example: open Catalog → fill the search box with “rice” → assert that the search box contains “rice”. Quick record is optional: when enabled, clicking the screenshot taps the phone and records the step.

4. Save the Python test

  1. Choose Plain pytest for your first test. It keeps the test in one Python file.
  2. Click Preview to see the generated files. Choose a file in the dropdown to read it, or use Copy file code.
  3. Click Save test after recording. The output is saved under <output folder>/<module>/<test-name>/, usually inside generated/.

Page Object Model (POM) puts reusable controls and actions into page classes. Both creates Plain and POM, running Plain by default. Use Save page object if you only want a page class from the current screen.

5. Replay and read the result

  1. Put the app in the starting state your recording expects. Handle startup offers or permission prompts consistently.
  2. Save your latest steps, choose the saved test and click Run saved test.
  3. Read Run result. Passed means pytest executed the test successfully. A new, empty starter cannot be replayed until you record and save steps.
  4. After replay, click Attach session again to continue inspecting. Use Load recording to edit an existing saved flow.

Replay performs the recorded actions again. Use a test account for flows that change app data. Clearing or undoing recorded steps does not undo actions already performed on the phone.

When something is confusing

No controls or wrong screenshot?
Attach the correct app, then Refresh screen. A WebView may only expose native controls unless the app enables DOM debugging.
Copy buttons are disabled?
Select a control first. Coordinates are a point on the screen, not an element locator.
The screen changed?
Refresh and select the control again before acting.
A test failed?
Read the failing step and saved screenshot. If a control changed, Repair step can suggest a replacement. Confirm the app reached the right screen first.
Where are reports?
Recent runs appear in the recorder. Detailed logs, JUnit results and failure captures are saved in the configured state folder under runs/ (normally .vortex/runs/).
